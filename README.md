# EvuMusic — как запустить и подключить

## Архитектура

```
Desktop/EvuMusic/
  index.html, style.css, app.js   ← сайт (мини-апп)
  server/                          ← сайт + API + бот в одном процессе
    index.js
    db-init.js
    sync.py                        ← качает историю тгка → боту
    .env.example
```

**Как хранится музыка:**
1. Бот — **админ** твоего музыкального тгка → ловит новые аудио → пишет `file_id` в Neon (`channel_tracks`)
2. Либо запускаешь `sync.py` — Telethon перешлёт старые треки боту в ЛС, бот сохранит их
3. В мини-аппе: поиск → `/api/search` (Neon) → кнопка Play → бот **присылает аудио в чат** (не нужен стриминг)

---

## Шаг 1 — Neon (БД)

1. https://neon.tech → Create project
2. Скопируй **pooled** connection string → это `DATABASE_URL`

## Шаг 2 — сайт

Залей папку `EvuMusic` (только `index.html`, `style.css`, `app.js`) на хостинг:
- **Vercel**: `npx vercel` в папке EvuMusic
- **Netlify**: drag&drop
- **или** свой VPS

Получишь URL вида `https://evumusic.vercel.app` — это и будет `WEBAPP_URL`.

## Шаг 3 — сервер + бот (один процесс)

На VPS / локально:

```bash
cd Desktop/EvuMusic/server
npm install
copy .env.example .env
# отредактируй .env (BOT_TOKEN, DATABASE_URL, WEBAPP_URL, MUSIC_CHANNEL, ADMIN_IDS)
npm run db:init
npm start
```

**Если сервер на VPS** — проброси порт 8080 (или поставь nginx/caddy перед ним).  
**Если локально** — для Telegram нужен public URL: [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/):

```bash
cloudflared tunnel --url http://localhost:8080
```

В `.env` → `WEBAPP_URL` = этот https-URL (туннель или домен).

## Шаг 4 — BotFather

1. `/newbot` → получишь `BOT_TOKEN`
2. `/setuserdescription`:
```
Твоя музыка, всегда рядом. Поиск треков, личные плейлисты, избранное и плеер прямо в Telegram. Закрытый музыкальный клуб по приглашениям. Нажми /start, чтобы открыть EvuMusic.
```
3. Добавь бота **админом** музыкального канала (чтобы ловил аудио)

## Шаг 5 — наполнить базу треками

**Новые треки** — просто постить в тгк, бот сам сохранит.

**Старая история** — один раз:

```bash
pip install telethon python-dotenv
cd Desktop/EvuMusic/server
# в .env уже есть TG_API_ID, TG_API_HASH, TG_PHONE, BOT_USERNAME, MUSIC_CHANNEL
python sync.py
```

Войдешь по коду из Telegram, скрипт перешлёт аудио боту → всё в Neon.

## Как пользоваться

| Действие | Как |
|----------|-----|
| Открыть приложение | `/start` → кнопка **Открыть EvuMusic** |
| Поиск | В приложении: Поиск → ввод названия |
| **Расширенный поиск** | Кнопка под строкой поиска — ищет **только по тгку** (Neon) |
| Слушать | Кнопка ▶ — бот пришлёт трек в чат |
| Инвайт | `/invite` (только админ) → ссылка `t.me/бот?start=inv_КОД` |
| Статистика | `/stats` (админ) |

## API (для фронта)

- `GET /api/health` — проверка
- `GET /api/search?q=` — поиск (канал + демо)
- `GET /api/advanced?q=` — расширенный поиск по каналу
- `GET /api/tracks` — лента канала
- `POST /api/send` — `{initData, trackId}` → бот шлёт аудио в ЛС

## Темы

В приложении: Настройки → Оформление → Синяя / Белая / Чёрная.

## Частые проблемы

| Проблема | Решение |
|----------|---------|
| Кнопка не открывает сайт | `WEBAPP_URL` должен быть **https** и без `/` на конце |
| «Не удалось отправить» | Пользователь не нажимал `/start` боту — бот не может ЛС |
| Пустой поиск | Бот не админ канала, или история не синхронизирована (`sync.py`) |
| Neon ошибка SSL | В `DATABASE_URL` должен быть `?sslmode=require` |


## Обложки и поддержка проекта

- Для каждой композиции сразу создаётся персональная fallback-обложка с названием и исполнителем.
- Затем приложение ищет точное совпадение трека только в Deezer. Если Deezer не находит трек, выполняется точный поиск в SoundCloud и используется только `artwork_url` самого трека (никогда не аватар исполнителя/пользователя).
- Случайные фотографии исполнителей не используются как обложки треков.
- Баннер «Поддержать проект» на главной странице ведёт на https://www.donationalerts.com/r/evumusic.

## Обновление обложек и баннера поддержки

- Баннер DonationAlerts автоматически показывается на всех разделах, включая страницы просмотра альбома и плейлиста; на странице «Настройки» баннера нет.
- Обложки запрашиваются сервером: сначала точное совпадение трека и исполнителя в Deezer, затем — только при отсутствии совпадения — `artwork_url` самого трека SoundCloud.
- Аватар пользователя SoundCloud и фотографии исполнителей не используются как обложки.
- Изображения проксируются через `/api/cover/`, чтобы браузер не упирался в CORS и ограничения прямой загрузки CDN.
- После обновления нужно перезапустить RU backend и обновить страницу с очисткой кэша (Ctrl+F5). Кэш обложек браузера обновлён до версии v4.

## Локальный запуск RU backend (обложки и поиск альбомов)

Если открываешь `index.html` напрямую через `file://`, перед использованием поиска запусти `start-ru-backend.bat` из корневой папки проекта. При первом запуске скрипт установит зависимости и поднимет API на `http://localhost:8001`. Окно сервера должно оставаться открытым, пока работает плеер.

Проверка: открой `http://localhost:8001/api/health` — должен появиться JSON с `"ok": true`.

## Поиск альбомов

В разделе «Поиск» переключись на вкладку «Альбомы», введи название альбома или исполнителя. Каталог загружается из Deezer; при открытии альбома показывается список композиций с доступными 30-секундными превью. Обложка альбома используется для его треков. Поиск обложек отдельных треков остаётся строго Deezer → SoundCloud (`artwork_url` самого трека).
